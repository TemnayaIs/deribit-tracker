# Deribit price tracker

Сервис раз в минуту забирает с биржи [Deribit](https://docs.deribit.com/) индексные цены `btc_usd` и `eth_usd`,
сохраняет их в PostgreSQL и отдаёт через HTTP API на FastAPI.

## Стек

Python 3.11, FastAPI, SQLAlchemy 2, PostgreSQL 16, Celery (брокер Redis), aiohttp, pytest, Docker Compose.

## Быстрый старт

Нужны Docker и Docker Compose.

```bash
docker compose up --build
```

Поднимутся контейнеры:

| сервис    | что делает                                                        |
|-----------|-------------------------------------------------------------------|
| `db`      | PostgreSQL                                                        |
| `redis`   | брокер для Celery                                                 |
| `migrate` | один раз создаёт таблицы и завершается                            |
| `api`     | FastAPI на http://localhost:8000 (документация: `/docs`)          |
| `worker`  | Celery worker, выполняет задачу сбора цен                         |
| `beat`    | Celery beat, раз в `FETCH_INTERVAL_SECONDS` (60) ставит задачу    |

Первые данные появятся примерно через минуту. Остановить: `docker compose down` (данные сохранятся в volume `pgdata`;
`docker compose down -v` удалит и их).

## API

Все методы — `GET`, параметр `ticker` обязателен и принимает `btc_usd` или `eth_usd` (регистр не важен).
Неизвестный или пропущенный тикер — `422`.

| метод                  | описание                                                                    |
|------------------------|-----------------------------------------------------------------------------|
| `GET /prices`          | все сохранённые цены тикера (по возрастанию времени), `limit`/`offset`     |
| `GET /prices/latest`   | последняя цена; `404`, если данных ещё нет                                  |
| `GET /prices/by-date`  | цены в диапазоне `date_from` ... `date_to` (UNIX-время, секунды, включительно). Любая из границ необязательна, `limit`/`offset` |
| `GET /health`          | проверка, что сервис жив                                                    |

Примеры:

```bash
curl "localhost:8000/prices/latest?ticker=btc_usd"
# {"ticker":"btc_usd","price":61007.52,"timestamp":1792042901}

curl "localhost:8000/prices?ticker=eth_usd&limit=10"

curl "localhost:8000/prices/by-date?ticker=btc_usd&date_from=1792042800&date_to=1792046400"
```

Формат строки: `ticker` — тикер, `price` — индексная цена, `timestamp` — UNIX-время (секунды) момента получения цены.

## Конфигурация

Переменные окружения (пример — `.env.example`):

| переменная                | по умолчанию                         |
|---------------------------|--------------------------------------|
| `DATABASE_URL`            | `postgresql+psycopg://postgres:postgres@localhost:5432/prices` |
| `REDIS_URL`               | `redis://localhost:6379/0`           |
| `DERIBIT_BASE_URL`        | `https://www.deribit.com/api/v2`     |
| `FETCH_INTERVAL_SECONDS`  | `60`                                 |
| `REQUEST_TIMEOUT_SECONDS` | `10`                                 |

## Запуск без Docker

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env              # поправьте адреса БД и Redis при необходимости
python -m app.init_db             # создать таблицы
uvicorn --factory app.main:create_app --port 8000
celery -A app.celery_app worker --loglevel=info      # в отдельном терминале
celery -A app.celery_app beat --loglevel=info        # в отдельном терминале
```

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Тесты не требуют ни PostgreSQL, ни Redis, ни интернета: API проверяется на SQLite в памяти, клиент Deribit — на локальном
фейковом сервере, который поднимается на aiohttp прямо в тесте.


## Design decisions

**Слои вместо одного файла.** Роуты ничего не знают про SQL, SQL лежит в `PriceRepository`, а сетевой клиент ничего не знает
про БД. Задача Celery только склеивает их: взять цены у клиента и записать через репозиторий. Каждый слой тестируется отдельно.

**Без глобальных переменных.** Приложение создаётся функцией `create_app()`, сессия БД приходит в роуты через `Depends`,
клиенту Deribit `aiohttp`-сессия и адрес передаются в конструктор, время (`clock`) подставляется параметром, поэтому в тестах
его легко зафиксировать. Единственное имя уровня модуля — `celery_app`: Celery находит приложение именно так.
Подключение к БД в воркере создаётся лениво, один раз на процесс, и хранится в атрибуте базового класса задачи.

**Celery + beat + Redis.** Периодический запуск раз в минуту — это расписание Celery beat. Beat вынесен в отдельный
контейнер и запускается в единственном экземпляре, иначе задача ставилась бы дважды за тик. Результаты задач не храним
(`task_ignore_result`), так как они нигде не используются.

**async только там, где он нужен.** HTTP-клиент написан на `aiohttp`, чтобы запросить оба тикера параллельно. API и работа с БД
синхронные: FastAPI выполняет обычные `def`-роуты в пуле потоков, а лишний async-драйвер для такой нагрузки только усложнил бы
код. Из синхронной Celery-задачи асинхронная часть вызывается через `asyncio.run`.

**Деньги в `Numeric`, а не во `float`.** Цена хранится как `Numeric(20, 8)`, а ответ Deribit разбирается через
`Decimal(str(value))`, чтобы не тащить в базу артефакты двоичной арифметики. В JSON цена отдаётся числом.

**Время.** В базе `BIGINT` с UNIX-временем в секундах, как требует задание. Метка ставится локально в момент, когда ответ
получен, и одинакова для обоих тикеров одного запуска, так что точки двух валют за одну минуту легко сопоставить.
Минус: это время нашего сервера, а не биржи. Если нужна биржевая метка, можно взять `usOut` из ответа Deribit.

**Индекс `(ticker, timestamp)`.** Все запросы фильтруют по тикеру и часто по времени, а «последняя цена» — это сортировка по
времени в обратном порядке. Составной индекс покрывает все три метода.

**Один тикер упал — остальные сохраняются.** Ошибка по одному тикеру логируется, цена другого сохраняется. Если не получилось ничего,
задача падает с ошибкой, и это видно в логах. Повторы (retry) не настроены: следующий запуск через минуту всё равно придёт.

**Тикер как `Enum`.** Допустимые значения описаны в одном месте (`Ticker`), от них зависят и валидация API (`422` на
незнакомый тикер), и список валют для сбора. Чтобы добавить валюту, достаточно добавить строку в enum.

**Лимиты в «всех данных».** Метод «все данные по валюте» принимает `limit` (по умолчанию 1000, максимум 10 000) и `offset`,
иначе через несколько недель сбора ответ стал бы огромным.

**Таблицы создаёт `init_db`.** Для одной таблицы я не стал подключать Alembic: отдельный контейнер `migrate` один раз
вызывает `create_all`. Когда схема начнёт меняться, правильный шаг — Alembic.

## Что можно улучшить

- Alembic для миграций.
- Хранить цены не в одной таблице, а секционировать по времени, если данных станет очень много.
- Метрики и алерты, если сбор данных остановился.
- Отдельный тестовый прогон с настоящим PostgreSQL в CI.
